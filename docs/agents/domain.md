# Domain Docs

工程技能在探索代码库时如何消费本仓库的领域文档。

## 探索前阅读以下文件

- **`CONTEXT.md`**（仓库根目录）
- **`docs/adr/`** — 阅读与你即将处理区域相关的 ADR。

若上述文件不存在，**静默继续**。不要标记缺失，不建议立即创建。`/domain-modeling` 技能（通过 `/grill-with-docs` 和 `/improve-codebase-architecture` 触发）会在术语或决策实际得出时惰性创建它们。

## 文件结构

Single-context 仓库：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-xxx.md
│   └── 0002-xxx.md
└── src/
```

## 使用术语表的词汇

当你的输出中命名了一个领域概念（Issue 标题、重构提案、假设、测试名称），使用 `CONTEXT.md` 中定义的术语。不要使用术语表明确避免的同义词。

如果需要的概念不在术语表中，这是一个信号——要么你在发明项目未使用的语言（重新考虑），要么是一个真实的缺口（标记给 `/domain-modeling`）。

## 标记 ADR 冲突

若你的输出与现有 ADR 矛盾，显式标记出来，而不是静默覆盖：

> _与 ADR-0007（xxx）冲突——但值得重新讨论，因为…_
