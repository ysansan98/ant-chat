# P4：主窗口 UI Shell

## 目标

- 在核心能力可用后，重构主窗口为 Codex-like 布局。

## 范围

- 左侧对话列表。
- 工作区切换入口。
- 工具区展示 MCP、Native Tools、Skills 状态。
- 中央聊天区保留现有能力。
- 对话列表按当前工作区过滤。

## 交付物

- 主窗口 Shell。
- 工作区切换 UI。
- 工具区。

## 实现要点

### 主窗口结构

主窗口采用 Codex-like 布局：

- 左侧：工作区入口 + 对话列表。
- 中间：聊天区。
- 侧边工具区：MCP、Native Tools、Skills 状态。
- 输入框上方：复杂任务进度列表和审批提示。

### 对话过滤

- conversation 创建时写入 `workspace_path`。
- 切换工作区后，列表只查询当前 `workspace_path` 下的会话。
- 默认工作区的会话也必须有稳定归属，避免和未设置工作区的历史数据混在一起。

### 工具区

工具区只展示能力状态，不在本阶段实现复杂配置：

- Native Tools：展示启用状态。
- MCP：展示连接状态和入口。
- Skills：展示已导入 skill 数量或列表入口。

### 回归边界

- 不改变聊天核心发送流程。
- 不改变 Agent Runtime 协议。
- 复杂任务进度列表仍由 P2 的事件驱动，只调整布局位置。

## 验收标准

- AC-P4-1：主窗口包含工作区入口、对话列表、工具区、聊天区。
- AC-P4-2：切换工作区后，对话列表按工作区刷新。
- AC-P4-3：工具区能展示 Native Tools 和 Skill 状态。
- AC-P4-4：聊天区在新 Shell 中仍可正常发送和接收消息。
- AC-P4-5：复杂任务进度列表在新 Shell 中仍显示在输入框上方。
