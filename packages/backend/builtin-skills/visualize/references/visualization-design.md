# Visualization 设计规则

仅在需要具体构图时加载本文。它补充主 skill 的生成约束，不改变 HTML fragment 合同。

## 解释器和模拟器

- 用一组紧凑控件、一个主视觉和最多一行当前状态说明。只有变化中的指标是核心时才增加最多三个摘要值。
- 步骤播放只更新一个当前视觉；不要同时堆叠公式、参数面板、步骤卡片和指标卡片。
- 参数变化后立即更新结果，并把当前值紧挨控件显示。给参数合理初值、单位和边界；不要把最大值当成推荐值。

## 图表和时间线

- 一次性数据分析直接从图表开始；把值、单位和关键结论放在轴、标记或注释附近，不要另造无关 KPI 行。
- 序列或并行工作使用共享时间轴和对齐泳道；把等待、瓶颈和总时长标在时间轴或泳道内。
- 多系列使用稳定的颜色、文字、形状或线型映射。只在无法直接标记时添加图例。
- 简单图表优先使用内联 SVG。只有明显降低复杂度时才使用白名单 CDN 图表库；使用库前确认版本、SRI 和脚本加载方式都符合合同。
- 每个 SVG、canvas 或 widget 都要有 role 与可访问名称，或提供可见文本摘要。悬停信息必须有键盘可访问的静态替代。

## 地图和空间信息

- 让地图成为主视觉，只保留一个紧凑的选择或详情区域。
- 使用可信的已发布 GeoJSON/TopoJSON 和明确来源的经纬度，并在 fragment 内包含所需数据。不要猜测行政边界、手绘轮廓或依赖运行时网络下载。
- 点、区域和标签必须在完整上下文中可辨认；局部点位不能漂浮在空白画布上。

## 表单和原型

- 每个输入都配可见 label；错误信息放在输入附近并保持足够空间。使用原生 button、input、select、textarea，保持默认 tab 顺序。
- 原型只模拟用户需要检查的状态和路径。不要为了像产品截图而加入不可交互的导航、搜索、筛选和假数据面板。
- 控件组用 .viz-controls 并允许折行；窄屏下字段堆叠。不要用固定宽度或横向滚动掩盖布局问题。
- 动态值可以写入 style 属性；柱状图、进度条和位置变化优先使用 SVG 的 width、height、x、y、transform 等属性，HTML 状态优先使用 data-\* 和 class 切换。

## 动画和主题

- 只在状态变化时动画；不要循环、自动播放或用淡入替代真实状态过渡。优先 transform 和 opacity，避免在每帧读取并写入布局。
- prefers-reduced-motion: reduce 下关闭或缩短动画，并确保不依赖动画才能理解结果。
- 不硬编码白色面板、黑色文字、浅色背景或固定色板。表面使用对应的 --viz-\* 变量；颜色承担语义时同时提供文字、形状或线型。
